# 配置说明

## Backend 配置（BackendConfig）

Backend 是框架的核心可插拔层，通过 `BackendConfig` 控制队列、锁和调度注册表使用内存还是 Redis 实现。

```python
from async_scheduler.backends import BackendConfig, BackendFactory

config = BackendConfig(
    # 模式选择
    distributed_mode=False,       # True = 启用 Redis 路径

    # Backend 类型
    queue_type="memory",          # "memory" | "redis"
    lock_type="memory",           # "memory" | "redis"
    registry_type="memory",       # 当前仅 "memory"（schedule registry 本地持久化）

    # Redis 连接
    redis_url="redis://localhost:6379/0",

    # Lease / Heartbeat
    lease_ttl_seconds=30,         # worker lease 超时时间
    heartbeat_interval_seconds=10, # lease 续期间隔
)
```

## 服务容器（ServiceContainer）

通过 `build_service_container()` 一步构建所有服务组件：

```python
from async_scheduler.platform import build_service_container

# 内存模式（默认）
services = await build_service_container()

# Redis 分布式模式
from async_scheduler.backends import BackendConfig
config = BackendConfig(
    distributed_mode=True,
    queue_type="redis",
    lock_type="redis",
    redis_url="redis://localhost:6379/0",
    lease_ttl_seconds=30,
    heartbeat_interval_seconds=10,
)
services = await build_service_container(backend_config=config)
```

### ServiceContainer 包含的组件

| 属性 | 类型 | 说明 |
|------|------|------|
| `task_router` | `TaskRouter` | 任务创建入口，含配额检查 |
| `task_consumer` | `TaskConsumer` | 后台消费循环 |
| `task_executor` | `TaskExecutor` | 执行器（超时/重试/取消） |
| `cron_scheduler` | `CronScheduler` | 定时调度循环 |
| `reconciler` | `TaskReconciler` | 孤儿任务修复循环 |
| `queue_manager` | `QueueManager` | 封装 QueueBackend |
| `dag_engine` | `DAGEngine` | DAG 执行引擎 |
| `registry` | `CapabilityRegistry` | 能力注册表 |
| `quota_manager` | `TenantQuotaManager` | 多租户配额 |
| `lock_backend` | `LockBackend \| None` | 分布式锁（Redis 模式下有值）|
| `worker_registry` | `WorkerRegistry \| None` | Worker 心跳注册（Redis 模式）|

## 数据库配置

框架使用 SQLite 作为任务持久化存储，数据库文件默认位于 `data/scheduler.db`。

```bash
# 初始化 / 重置数据库
async-scheduler init-db-cmd --force
```

通过环境变量自定义：

```bash
DATABASE_URL=sqlite+aiosqlite:///./custom/path/scheduler.db async-scheduler api
```

## Reconciler 配置

`TaskReconciler` 通过 `ReconciliationConfig` 控制修复行为：

```python
from async_scheduler.platform import ReconciliationConfig, RepairStrategy

config = ReconciliationConfig(
    stuck_after_seconds=3600,           # 超过多久视为卡死
    repair_strategy=RepairStrategy.REQUEUE,  # REQUEUE | MARK_FAILED | IGNORE
    reconcile_interval_seconds=60,      # 修复循环间隔
)
```

## 配额配置

通过 API 或代码配置租户配额：

```bash
# API 方式
curl -X POST http://127.0.0.1:8000/tenants \
  -H 'Content-Type: application/json' \
  -d '{"name":"team-a","config":{"max_queued":20,"max_running":5}}'

# 更新配额
curl -X PATCH http://127.0.0.1:8000/tenants/<id> \
  -H 'Content-Type: application/json' \
  -d '{"config":{"max_queued":50,"max_running":10}}'
```

## 环境变量速查

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `REDIS_URL` | - | Redis 连接 URL，设置后自动启用分布式模式 |
| `TEST_REDIS_URL` | - | 测试专用 Redis URL，仅影响 live Redis 测试套件 |
| `DATABASE_URL` | `sqlite+aiosqlite:///./data/scheduler.db` | SQLite 数据库路径 |
| `LOG_LEVEL` | `INFO` | 日志级别 |

## 分布式部署建议

详见 `docs/runtime/distributed-deployment-guide.md`，要点：

1. **共享 Redis**：多个 worker 进程必须指向同一个 Redis 实例
2. **Lease TTL**：建议 `lease_ttl_seconds=30`，`heartbeat_interval_seconds=10`（TTL 的 1/3）
3. **Reconciler 单实例**：建议只运行一个 reconciler 实例，避免并发修复竞争
4. **数据库**：SQLite 适合单机；多节点建议迁移到 PostgreSQL（需自行适配 repository 层）
