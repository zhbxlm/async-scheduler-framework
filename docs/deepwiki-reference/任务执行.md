# 任务执行

## 执行流程

```
TaskConsumer.dequeue()
  │
  ├── [内存模式]
  │     └── InMemoryQueueBackend.dequeue()
  │
  └── [Redis 模式]
        ├── RedisQueueBackend.dequeue()
        ├── Create ExecutionAttempt (status=RUNNING, lease_token=uuid)
        ├── LockBackend.acquire(f"task:{task_id}", lease_token, ttl=30s)
        ├── WorkerRegistry.register_heartbeat()
        └── background: extend_lease() every 10s

        └── TaskExecutor.execute(task)
              ├── CapabilityRegistry.dispatch(task_type, payload)
              ├── asyncio.wait_for(handler(task), timeout=timeout_seconds)
              │
              ├── on success:
              │     └── CompletionDedupBackend.claim_once(task_id)
              │           └── TaskCompletionNode.process(task, SUCCESS)
              │
              └── on failure/timeout:
                    ├── retry_count < max_retries → RETRY → re-enqueue
                    └── retry exhausted → TaskCompletionNode.process(task, FAILED/TIMEOUT)
```

## TaskExecutor

```python
from async_scheduler.executor.executor import TaskExecutor

executor = TaskExecutor(
    registry=registry,
    timeout_seconds=3600,    # 默认超时
    max_retries=3,           # 默认最大重试
)

# 取消正在执行的任务
await executor.cancel(task_id)

# 获取当前运行中任务数
count = executor.get_running_count()
```

## 执行超时

- `timeout_seconds` 在 TaskCreate 时设置，优先级最高
- 未指定则使用 executor 全局默认值
- 超时触发 `asyncio.TimeoutError`，最终状态为 `TIMEOUT`

## 重试语义

```python
# 创建任务时指定重试次数
task = TaskCreate(
    name="reliable-task",
    payload={"capability": "flaky_service"},
    max_retries=3,          # 最多重试 3 次，共执行 4 次
    timeout_seconds=60,     # 每次执行最多 60 秒
)
```

重试时每次创建新的 ExecutionAttempt，旧的 attempt 状态更新为 `FAILED`。

## 完成幂等性（CompletionDedupBackend）

分布式场景下，网络抖动可能导致完成信号被重复发送。`CompletionDedupBackend` 确保每个任务只被完成一次：

```python
# claim_once 返回 True 表示当前 worker 赢得了完成权
claimed = await completion_backend.claim_once(task_id, lease_token)
if claimed:
    await task_repo.update(task_id, status=TaskStatus.SUCCESS)
    # 发送回调等...
```

## 执行尝试（ExecutionAttempt）诊断

```bash
# 查看任务所有执行记录
curl http://127.0.0.1:8000/tasks/{task_id}/attempts

# 查看最新执行记录
curl http://127.0.0.1:8000/tasks/{task_id}/attempts/latest

# 查看任务完整历史（含汇总统计）
curl http://127.0.0.1:8000/tasks/{task_id}/history

# 查看单任务 lease 状态
curl http://127.0.0.1:8000/debug/leases/{task_id}
```

## 常见执行异常诊断

### 任务卡在 RUNNING

```bash
# 1. 检查是否有 lease
curl http://127.0.0.1:8000/debug/leases/{task_id}

# 2. 检查异常 lease 汇总
curl http://127.0.0.1:8000/debug/summary
# 关注 leases.anomaly_summary.running_without_lock

# 3. 手动触发修复
curl -X POST http://127.0.0.1:8000/reconciler/run
```

### attempt 状态 ABANDONED 但任务还是 RUNNING

这是 reconciler 尚未修复的窗口期，等待下次 reconciler 循环或手动触发修复。

### lease TTL 即将耗尽

心跳续期失败（worker 崩溃 / GC 停顿）。reconciler 在 `stuck_after_seconds` 后自动处理。
