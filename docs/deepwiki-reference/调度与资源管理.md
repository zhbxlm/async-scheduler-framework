# 调度与资源管理

## 任务路由（TaskRouter）

`TaskRouter` 是任务创建的入口，负责配额检查 → 持久化 → 入队三步：

```python
from async_scheduler.platform import build_service_container

services = await build_service_container()

task = await services.task_router.create_task(TaskCreate(
    name="my-task",
    payload={"capability": "echo", "message": "hello"},
    tenant_id="tenant-a",
    priority=0,
))
```

### 任务优先级

数值越小优先级越高，默认为 `0`。同优先级按 FIFO 处理。

### 延时任务

```python
from datetime import datetime, timedelta

task = await services.task_router.create_task(TaskCreate(
    name="delayed-task",
    payload={"capability": "echo"},
    scheduled_at=datetime.utcnow() + timedelta(minutes=30),
))
```

延时任务进入 delayed queue，到时间后自动 promote 到 ready queue。

## 队列管理（QueueManager）

```python
# 查看队列大小
sizes = await services.queue_manager.size()

# 当前排队任务数
count = await services.queue_manager.get_queue_count()

# 已调度（延时）任务数
scheduled = await services.queue_manager.get_scheduled_count()

# 取消排队中的任务
cancelled = await services.queue_manager.cancel(task_id)

# 发现所有 capability 队列
caps = await services.queue_manager.discover_capabilities()
```

## 多租户配额（TenantQuotaManager）

```python
from async_scheduler.platform.quota import TenantQuotaManager

qm = TenantQuotaManager()

# 配置租户配额
qm.configure_tenant("tenant-a", max_queued=50, max_running=10)

# 查看配额统计
stats = qm.stats()

# 配额检查（TaskRouter 内部自动调用）
# 超出配额时抛出 QuotaExceededError
```

### 通过 API 管理配额

```bash
# 创建租户并设置配额
curl -X POST http://127.0.0.1:8000/tenants \
  -d '{"name":"team-a","config":{"max_queued":20,"max_running":5}}'

# 更新配额
curl -X PATCH http://127.0.0.1:8000/tenants/{id} \
  -d '{"config":{"max_queued":100,"max_running":20}}'

# 查看当前配额使用
curl http://127.0.0.1:8000/quota/stats
```

## TaskReconciler — 孤儿任务修复

Reconciler 在后台定期检测卡死 / 孤儿任务并根据策略自动修复：

```python
from async_scheduler.platform import ReconciliationConfig, RepairStrategy

config = ReconciliationConfig(
    stuck_after_seconds=3600,              # 超过 1h 视为卡死
    repair_strategy=RepairStrategy.REQUEUE, # REQUEUE | MARK_FAILED | IGNORE
    reconcile_interval_seconds=60,
)
```

修复逻辑：
1. 查找状态为 `RUNNING` 但无有效 lease 的任务
2. 查找 ExecutionAttempt 状态为 `ABANDONED` 的任务
3. 根据 `repair_strategy` 决定 requeue 还是 mark_failed

### 手动触发

```bash
# API
curl -X POST http://127.0.0.1:8000/reconciler/run

# CLI
async-scheduler reconcile
```

### 查看修复历史

```bash
curl http://127.0.0.1:8000/reconciler/history
curl 'http://127.0.0.1:8000/reconciler/history?action=requeue'
curl 'http://127.0.0.1:8000/reconciler/history?task_id=<task_id>'
```

## 资源管理扩展组件

以下组件是 deepwiki 对齐路线图中的高级扩展，当前为可选配置：

### ActorPoolManager

管理 capability 对应的 Actor 池，支持自动扩缩容（未完全实现）：

```bash
curl http://127.0.0.1:8000/actors/capabilities
curl http://127.0.0.1:8000/actors/{capability}/stats
```

### ResourceManager

跟踪集群资源使用，生成伸缩决策：

```bash
curl http://127.0.0.1:8000/resources/stats
curl http://127.0.0.1:8000/resources/scale-history
```

### ClusterRegistry

多集群注册与 capability 路由：

```bash
curl http://127.0.0.1:8000/clusters
curl http://127.0.0.1:8000/clusters/by-capability/{capability}
```
